# NovaGems v1.1.4 — size report

Medición tomada sobre artefactos reales con tamaños comprimidos del ZIP/JAR. La línea base se capturó antes de cambiar dependencias o empaquetado.

## Línea base v1.1.3

- Archivo: `NovaGems-1.1.3.jar`
- Tamaño total: 19,402,712 bytes (18.504 MiB)
- Clases y recursos de NovaGems: 224,959 bytes comprimidos
- SQLite Java: 204,504 bytes comprimidos
- Binarios nativos de SQLite: 14,140,869 bytes comprimidos
- MySQL Connector/J relocalizado: 2,414,296 bytes comprimidos
- HikariCP relocalizado: 147,618 bytes comprimidos
- `META-INF`: 18,006 bytes comprimidos
- Otros, incluido Protobuf: 1,750,742 bytes comprimidos

Los binarios nativos multi-plataforma de SQLite dominaban el JAR; Connector/J y su dependencia Protobuf eran el segundo bloque relevante. El código propio era aproximadamente 0.215 MiB comprimido.

## Resultado v1.1.4

| Artefacto | Tamaño total | Contenido de runtime |
|---|---:|---|
| `NovaGems-1.1.4.jar` | 257,559 bytes (0.246 MiB) | Ninguna dependencia embebida; usa `plugin.yml libraries` |
| `NovaGems-1.1.4-offline.jar` | 19,321,402 bytes (18.426 MiB) | SQLite, nativos, Connector/J, Protobuf y HikariCP |

El slim es 19,145,153 bytes menor que v1.1.3, una reducción de 98.6726%. El offline conserva deliberadamente el coste de las dependencias para poder iniciar sin descargas de Maven; queda 81,310 bytes por debajo del fat JAR anterior debido principalmente a eliminar relocations innecesarias.

Dependencias declaradas, exactamente iguales a las usadas al compilar:

- `com.zaxxer:HikariCP:7.0.2`
- `org.xerial:sqlite-jdbc:3.51.1.0`
- `com.mysql:mysql-connector-j:9.6.0`
- Transitiva de Connector/J: `com.google.protobuf:protobuf-java:4.31.1`

Estas cifras se recapturaron después del `clean test build` final.
